# CodeQL로 소스코드 취약점 탐지하기

> CodeQL의 동작 원리를 이해하고, 직접 쿼리를 작성해 SQL Injection과 Command Injection을 탐지해보는 실습 기록

---

## 0. CodeQL이란?

**CodeQL**은 GitHub(구 Semmle)이 개발한 **정적 분석(SAST) 엔진**이다.  
일반적인 grep이나 시그니처 기반 스캐너와 달리, 소스코드를 **관계형 데이터베이스**로 변환한 뒤 SQL과 유사한 전용 쿼리 언어 **QL**로 취약점 패턴을 질의하는 방식이다.

```
소스코드 → [CodeQL 빌드] → .db (CodeQL Database) → [QL 쿼리 실행] → 결과(alert)
```

GitHub Advanced Security(GHAS)의 코드 스캐닝 기능이 내부적으로 CodeQL을 사용한다.

---

## 1. 핵심 원리: 코드를 데이터베이스로 보는 시각

### 1-1. CodeQL Database 구조

CodeQL은 분석 대상 코드를 빌드하면서 다음 정보를 추출해 DB화한다.

| 구성요소 | 설명 |
|---|---|
| **AST (Abstract Syntax Tree)** | 소스 파싱 결과, 구문 구조 |
| **CFG (Control Flow Graph)** | 실행 흐름, 분기/루프 |
| **DFG (Data Flow Graph)** | 값이 어떻게 전파되는지 |
| **Call Graph** | 함수 호출 관계 |
| **Type Information** | 타입 추론 결과 |

이 정보들이 전부 `.db` 디렉터리 안에 **관계(relation) 테이블** 형태로 저장된다.

### 1-2. QL (Query Language) 기초

QL은 Datalog 기반의 논리형 쿼리 언어다. SQL처럼 `from / where / select` 구조를 가진다.

```ql
// 가장 단순한 QL 쿼리 구조
from [타입] [변수]
where [조건]
select [출력할 것], [메시지]
```

핵심 개념 세 가지:

**① 클래스(Class)**  
AST 노드, 함수, 변수 등 코드 요소를 타입으로 모델링한다.  
예: `Call`, `Attribute`, `BinaryExpr`, `Name`, `AssignStmt` 등

**② 술어(Predicate)**  
조건을 정의하는 함수. 조건이 참이면 해당 사실이 성립한다.

```ql
predicate isExecuteCall(Call c) {
  c.getFunc().(Attribute).getName() = "execute"
}
```

**③ Data Flow / Taint Tracking**  
가장 강력한 기능. Source(입력) → Sink(위험 지점)까지 데이터가 흐르는 경로를 자동 추적한다.

```
[Source] HTTP 파라미터 입력
    ↓  (sanitizer 없이 전달)
[Sink]  SQL 쿼리 실행 → SQL Injection!
```

## 2. 환경 세팅 (Windows + VS Code)

### 2-1. CodeQL VS Code 확장 설치

VS Code Extensions(`Ctrl+Shift+X`) → `CodeQL` 검색 → **GitHub Security Lab** 설치

설치하면 CLI가 자동으로 함께 설치된다.  
단, CLI가 PATH에 자동 등록되지 않아서 수동으로 추가해야 한다.

### 2-2. CLI 경로 찾기 및 PATH 등록

```powershell
# CLI 경로 탐색
Get-ChildItem -Path "$env:USERPROFILE\.vscode" -Filter "codeql.exe" -Recurse -ErrorAction SilentlyContinue | Select-Object FullName
```

찾은 경로를 PATH에 등록:

```powershell
[System.Environment]::SetEnvironmentVariable(
  "Path",
  $env:Path + ";C:\Users\[사용자명]\AppData\Roaming\Code\User\globalStorage\github.vscode-codeql\distribution1\codeql",
  "User"
)
```

VS Code 재시작 후 확인:

```powershell
codeql version
# CodeQL command-line toolchain release 2.25.6
```

### 2-3. qlpack.yml 설정

쿼리 폴더에 반드시 `qlpack.yml`이 있어야 표준 라이브러리를 사용할 수 있다.

```yaml
# queries/qlpack.yml
name: my-python-queries
version: 0.0.1
dependencies:
  codeql/python-all: "*"
```

의존성 설치:

```powershell
codeql pack install queries/
```

> **주의**: VS Code에서 쿼리를 실행하려면 `queries/` 폴더 자체를 `File → Open Folder`로 열어야 qlpack이 인식된다.

## 3. 실습: 취약한 Flask 앱 분석

### 3-1. 대상 코드

```python
# vuln_app.py

import sqlite3
import os
from flask import Flask, request

app = Flask(__name__)

# [취약점 1] SQL Injection
@app.route('/user')
def get_user():
    username = request.args.get('username')
    conn = sqlite3.connect('users.db')
    query = "SELECT * FROM users WHERE name = '" + username + "'"  # ❌
    result = conn.execute(query)
    return str(list(result))

# [취약점 2] Command Injection
@app.route('/ping')
def ping():
    host = request.args.get('host')
    output = os.popen("ping -c 1 " + host).read()  # ❌
    return output

if __name__ == '__main__':
    app.run()
```

### 3-2. CodeQL Database 생성

```powershell
codeql database create ./vuln_db --language=python --source-root=.
# Successfully created database at C:\Users\jinse\codeql-lab\vuln_db
```

### 3-3. SQL Injection 탐지 쿼리

처음에는 TaintTracking 기반 쿼리를 시도했지만, `request.args.get()` 반환값을 Source로 모델링하는 과정에서 버전 호환성 문제가 발생했다. 결국 **AST 레벨에서 직접 패턴을 잡는 방식**으로 전환했다.

쿼리 로직은 다음과 같다:
1. `execute()` 메서드 호출을 찾는다
2. 첫 번째 인자로 전달된 변수명을 추출한다
3. 그 변수에 문자열 연결(`+`)로 값이 할당된 곳을 찾는다

```ql
/**
 * @name SQL Injection
 * @description execute()에 문자열 연결 변수가 전달됨
 * @kind problem
 * @problem.severity error
 * @id python/sql-injection-custom
 */

import python

from Call execCall, Attribute execAttr, Name argName,
     AssignStmt assign, Name targetName, BinaryExpr binop
where
  execCall.getFunc() = execAttr and
  execAttr.getName() = "execute" and
  execCall.getArg(0) = argName and
  assign.getATarget() = targetName and
  targetName.getId() = argName.getId() and
  assign.getValue() = binop and
  binop.getOp() instanceof Add
select execCall,
  "SQL Injection: execute()에 문자열 연결로 만들어진 변수가 전달됨"
```

**탐지 결과 (`vuln_app.py:13:14`):**

![SQL Injection 탐지 결과](/assets/img/codeql-sqli-result.png)

오른쪽 패널에서 `vuln_app.py:13:14` — `conn.execute(query)` 라인이 정확히 탐지된 것을 확인할 수 있다.

### 3-4. Command Injection 탐지 쿼리

`os.popen()` 은 인자를 변수 없이 직접 BinaryExpr(`"ping -c 1 " + host`)로 전달하는 패턴이라 SQL Injection 쿼리와 다르게 작성했다.

```ql
/**
 * @name Command Injection
 * @description os.popen()에 문자열 연결이 직접 전달됨
 * @kind problem
 * @problem.severity error
 * @id python/cmd-injection-custom
 */

import python

from Call popenCall, Attribute popenAttr, BinaryExpr binop
where
  popenCall.getFunc() = popenAttr and
  popenAttr.getName() = "popen" and
  popenCall.getArg(0) = binop and
  binop.getOp() instanceof Add
select popenCall,
  "Command Injection: popen()에 문자열 연결이 직접 전달됨"
```

**탐지 결과 (`vuln_app.py:20:14`):**

![Command Injection 탐지 결과](/assets/img/codeql-cmdi-result.png)

오른쪽 패널에서 `vuln_app.py:20:14` — `os.popen("ping -c 1 " + host)` 라인이 정확히 탐지된 것을 확인할 수 있다.

## 4. 실습 중 마주친 트러블슈팅

| 문제 | 원인 | 해결 |
|---|---|---|
| `codeql` 명령어 인식 안 됨 | VS Code 확장이 PATH 자동 등록 안 함 | 수동으로 PATH 등록 후 재시작 |
| `could not resolve module` | qlpack.yml 없음 | `qlpack.yml` 생성 + `pack install` |
| VS Code에서 쿼리 실행 실패 | workspace 루트가 queries 폴더가 아님 | queries 폴더를 `Open Folder`로 열기 |
| `concat` 변수명 에러 | QL 예약어 충돌 | 변수명을 `binop`으로 변경 |
| TaintTracking Source 미탐지 | Flask 모델링이 현재 버전과 불일치 | AST 레벨 직접 패턴 매칭으로 전환 |

## 5. grep vs CodeQL

| 항목 | grep / 정규식 | CodeQL |
|---|---|---|
| 분석 수준 | 텍스트 패턴 | AST + 의미론적 분석 |
| 데이터 흐름 추적 | ❌ 불가 | ✅ Source → Sink 추적 |
| 함수 간 분석 | ❌ 불가 | ✅ 인터프로시저 분석 |
| False Positive | 높음 | 낮음 (sanitizer 모델링 가능) |
| 커스텀 쿼리 | 정규식만 | QL로 임의의 패턴 표현 가능 |
| 학습 비용 | 낮음 | 중~높음 |
